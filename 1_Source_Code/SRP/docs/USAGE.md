# Usage guide

This is research code developed incrementally over the course of a
single project, not a packaged CLI tool. Every script (Python and R
alike) configures its inputs/outputs with plain variables near the
bottom of the file (inside `if __name__ == "__main__":` or a `main()`
function it calls) rather than `argparse` flags or a config file.
**To run a script: open it, search for the placeholder `XXXyour path`,
replace every occurrence with the actual path to your data, save, and
run.** Each file already contains several commented-out example
configurations (for different cohorts) directly above the active one —
these show you the expected directory structure and naming pattern to
follow.

`grep -rn "XXXyour path" src/` from the repo root lists every line that
still needs your input before a given script will run.

## 0. Setup

```bash
git clone <this-repo-url>
cd SRP
python -m venv .venv && source .venv/bin/activate   # or use conda
pip install -r requirements.txt
```

`torch` / `torch-geometric` / `fmcib` (used only by
`src/graph_neural_network/`) are the heaviest Python dependencies —
skip them if you don't need that branch. The single-cell analysis
(`src/scrna_seq_analysis/`) is R, not Python — see
[requirements_R.md](../requirements_R.md).

### Expected data layout

Data is not included in this repository. Wherever you keep it, that
location is what `XXXyour path` should be replaced with throughout
`src/`. The structure every script expects below that path (one
subfolder per cohort):

```
Dataset/
└── <CohortName>/                    e.g. Dataset002_ECResponse, TJH, SPCH, FUSCC
    ├── Image/                        CT images, <case_id>.nii.gz
    ├── Mask/                         tumor segmentation masks, <case_id>.nii.gz
    ├── FeatureMaps/
    │   └── feature_maps/             per-case feature maps (.pkl.gz), generated by
    │                                  TextureFeatureMapGenerate.py, consumed by
    │                                  SpatialTextureFeatureExtractor.py
    ├── PatientLabels.xlsx            clinical labels / ground truth (pCR, survival, etc.)
    ├── radiomics_features.csv        output of RadiomicsFeatureExtractor.py
    ├── spatial3d_features.csv        output of Spatial3DFeatureExtractor.py
    ├── spatial_texture_features.csv  output of SpatialTextureFeatureExtractor.py
    ├── model_results/                trained models, *_predictions_results.csv
    ├── visualizations/                figures from src/evaluation/
    └── survival_analysis/            outputs from src/survival_analysis/
```

Sub-cohorts (e.g. `TJH`, `SPCH`, `FUSCC` under `Dataset002_ECResponse` /
`Dataset004-NACI`) follow the same structure one level down.

Outputs written to a `manuscript/`-style folder (e.g. by
`BinormalAUC_BootstrapCI.py`) are just a results-table destination —
create that folder or edit the output path.

`src/scrna_seq_analysis/` (single-cell) expects a separate root of its
own (also spelled `XXXyour path` in those scripts — don't confuse it
with the imaging `Dataset/<CohortName>/` root above), laid out as:

```
<scRNA-seq-CT root>/
├── cellranger_output/
│   └── 1_cell_ranger_result/     raw CellRanger output per sample
└── scRNA_Results_new/            all pipeline outputs, one subfolder
    ├── 01_QC/                     per numbered stage (01_QC.R writes
    ├── 02_Integration/            here, 02_Integration.R reads 01_QC's
    ├── 03_Annotation/             output and writes its own, etc.)
    └── ...
```

### A note on file naming across this repo

Several stages (both Python and R) have more than one script covering
similar ground — e.g. `SapRadFramework.py` vs. the modular
`src/feature_extraction/` extractors, or (in `src/scrna_seq_analysis/`)
`03_CellTypeAnnotation_1step.R` / `_2step.R` / `_Heatmap.R` /
`03_CellType_Annotation.R`, and `04_Differential_Analysis.R` /
`04_DifferentialExpressionAnalysis.R` / `04_Proportion_DEG_SignificantClusters.R`.
These reflect genuine iterations made during the actual analysis (later
files fixing or superseding issues in earlier ones — several R scripts
say so directly in their header comments, e.g. "REVISED", "FIXED",
"Fixed filter() Conflict") rather than duplicates by accident. All are
kept for reproducibility/transparency about what was actually run;
check each file's header comment for what it changes relative to its
predecessor before assuming which one is "canonical" for your reuse.

## 1. Feature extraction (`src/feature_extraction/`)

Run in this order per cohort:

1. **`RadiomicsFeatureExtractor.py`** — PyRadiomics shape/first-order/
   texture features from `Image/` + `Mask/`. Uses `radiomics_config.yaml`
   in the same folder (feature classes/filters to extract — edit this
   file directly to change which PyRadiomics features are computed).
   Output: `radiomics_features.csv`.
2. **`TextureFeatureMapGenerate.py`** (or the SPCH-cohort variant
   `TextureFeatureMapGenerate_SPCH.py`) — generates the voxel-wise
   feature maps consumed by the next two steps. Output:
   `FeatureMaps/feature_maps/*.pkl.gz`.
3. **`Spatial3DFeatureExtractor.py`** — 3D spatial-heterogeneity
   features directly from `Image/` + `Mask/`. Output:
   `spatial3d_features.csv`.
4. **`SpatialTextureFeatureExtractor.py`** — spatial-texture /
   heterogeneity statistics (e.g. Moran's I) computed on the feature
   maps from step 2. Output: `spatial_texture_features.csv`.
   Supports `process_all_cases_parallel(n_jobs=...)` for multi-core runs.

## 2. Model training (`src/modeling/`)

- **`SpatialClassificationModel.py`** — trains the Spatial-only model
  (feature selection + XGBoost) from `spatial3d_features.csv` /
  `spatial_texture_features.csv`.
- **`RadiomicsClassificationModel.py`** — trains a Radiomics-only
  classifier from `radiomics_features.csv`.
- **`SpatialRadiomicsClassifier.py`** — the combined Spatial+Radiomics
  fusion pipeline (feature selection, model fit, fusion weighting).
- **`ComparsionClassificationModel_Dataset002ECResponse.py`** /
  **`ComparsionClassificationModel_Dataset004NACI.py`** — head-to-head
  comparison of Spatial vs. Radiomics vs. Fusion for each dataset,
  across cohorts (Test/TJH/SPCH or Test/SPCH/FUSCC).
- **`merge_features.py`** — utility to merge/reshape feature tables.
- **`DataLoader.py`** — shared NIfTI image/mask loading helper, imported
  by `SapRadFramework.py` / `SpaRadFramework_Fast.py`.
- **`SapRadFramework.py`** / **`SpaRadFramework_Fast.py`** — an earlier,
  monolithic feature-extraction-plus-caching framework from an earlier
  stage of the project (the `_Fast` variant adds a `CacheManager` for
  incremental/checkpointed runs). Superseded for most purposes by the
  modular extractors in `src/feature_extraction/`, kept here for
  reproducibility.
- **`MultiFeatureFusion_Dataset01.py`** / **`MultiFeatureFusion_Dataset02.py`**,
  **`RadSpatialFusionModel_Dataset002.py`**, **`MultiModalComparison.py`**
  — earlier multimodal fusion / comparison experiments from this
  project's development history, retained for completeness.

Trained model artifacts (e.g. `best_models.joblib` bundling the fitted
scalers/selectors/classifiers for all three models) and per-patient
prediction tables (`*_predictions_results.csv`, with columns
`case_id, true_label, spatial_probability, radiomics_probability,
fused_probability`) are written to each cohort's `model_results/`.
Everything downstream (evaluation, survival, external validation) reads
from these prediction CSVs.

### Optional: graph neural network branch (`src/graph_neural_network/`)

An alternative modeling approach explored during this project:
**`FMCIB_FeatureExtractor.py`** extracts voxel-wise foundation-model
(FMCIB) embeddings, **`VoxelGraphBuilder.py`** builds a patient graph
from them, and **`GNNClassificationBuilder.py`** trains a GNN classifier
on the graphs (see its module docstring for `--graph_dir` /
`--clinical_xlsx` / `--output_dir` example invocations). Requires
`torch` + `torch-geometric` + `fmcib`. Not part of the main
Spatial/Radiomics/Fusion pipeline used elsewhere in this repo.

## 3. Evaluation (`src/evaluation/`)

- **`PlotFigures.py`** — the core Nature-journal-style figure toolkit
  (`MedicalImagingVisualizer` class): ROC curves, calibration curves,
  DCA, confusion matrices, radar charts, probability distributions,
  metrics tables. Imported by most other scripts in this folder — not
  usually run standalone.
- **`PredictionFigures.py`** — end-to-end figure generation for a given
  cohort's predictions.
- **`PlotCaseFeatureMaps.py`** — per-case visualization of the
  extracted feature maps overlaid on the CT/mask.
- **`BinormalROCFit_Dataset002.py`** / **`BinormalROCFit_Dataset004NACI.py`**
  — fits a binormal (parametric) model to each cohort's predicted
  probabilities to produce smoothed ROC/DCA/calibration curves and a
  Bayesian-recalibrated per-patient probability. Use this when a
  cohort's raw predicted probabilities are heavily tied (common for
  shallow, few-feature XGBoost models on small-to-moderate n), which
  otherwise makes empirical ROC/DCA curves look like jagged
  staircases. Outputs go to a sibling `visualizations_binormal_fitted/`
  folder so the original raw-score figures are untouched.
- **`BinormalAUC_BootstrapCI.py`** — binormal AUC point estimate +
  bootstrap 95% CI (2,000 resamples) for every model/cohort.
- **`EvaluateModelOnSPCH_Dataset002.py`** — reproduces the
  Dataset002_ECResponse model and evaluates it on the SPCH external
  cohort in one script (imports both `PlotFigures.py` and
  `../survival_analysis/PlotSurvivalAnalysis.py`).
- **`PlotFiguresNewRadiomics_Dataset004NACI.py`** — figure suite for
  Dataset004-NACI's Test/SPCH/FUSCC cohorts plus a SHAP feature-
  importance comparison fit on the training cohort.

## 4. Survival analysis (`src/survival_analysis/`)

- **`SurvivalAnalysis.py`** — Cox proportional-hazards regression
  (binary risk-group and continuous-probability parameterizations) +
  Kaplan-Meier log-rank tests for DFS/OS, using `*_predictions_results.csv`
  and a clinical labels/survival Excel file
  (`case_id`, survival time/event columns). Outputs
  `cox_regression_results.csv`, `median_survival.csv`,
  `survival_report.txt` to `survival_analysis/`.
- **`PlotSurvivalAnalysis.py`** — Nature-style Kaplan-Meier /
  survival figure generation from the same inputs.

## 5. External validation (`src/external_validation/`)

- **`PredictNSCLC.py`** — loads a locked, already-trained model
  (`best_models.joblib`) and applies it to a *new* imaging cohort with
  no ground-truth labels (pure inference): merges that cohort's
  spatial3d/texture/radiomics feature CSVs, computes per-patient
  spatial/radiomics/fused probabilities, and assigns a binary risk
  group at the 0.5 cutoff on the fused probability. Use this as the
  template for scoring any new cohort with a model trained in step 2.

## 6. Biological validation (RNA-seq)

Cross-checks that a model's imaging-derived risk stratification
corresponds to a coherent tumor biology, using cohorts with *both* CT
imaging and RNA-seq (paired by case ID), scored with a locked model
from step 5.

### 6a. Bulk RNA-seq (`src/rnaseq_analysis/`, Python)

1. **`RNAseq_DEG_Analysis.py`** — differential expression between
   model-predicted risk groups via DESeq2 (`pydeseq2`): builds sample
   metadata (parses a GEO `series_matrix.txt.gz` if that's your data
   source), loads raw counts, filters low-count genes, fits the
   negative-binomial GLM, and exports full/significant DEG tables plus
   a ranked gene list for GSEA and VST-normalized counts for
   visualization.
2. **`RNAseq_Enrichment_Analysis.py`** — GSEA preranked (Hallmark/KEGG/
   GO Biological Process via `gseapy`) on the full ranked gene list,
   plus Enrichr over-representation analysis on the significant DEGs.
   **Note:** KEGG's "disease pathway" gene sets (e.g. Huntington's,
   Parkinson's, Alzheimer's) heavily overlap with core
   oxidative-phosphorylation/mitochondrial gene sets — if you see these
   among your top hits alongside a real OXPHOS signal, that is very
   likely this known curation artifact, not literal disease relevance.
   Check gene-set membership overlap before reporting such a result.
3. **`RNAseq_PlotFigures.py`** — Nature-style volcano plot, PCA,
   top-DEG heatmap, and GSEA/ORA summary plots from the outputs of the
   two scripts above.

### 6b. Single-cell RNA-seq (`src/scrna_seq_analysis/`, R / Seurat)

A full Seurat-based scRNA-seq pipeline on a paired CT+scRNA-seq
esophageal-cancer cohort (Dataset002_ECResponse), comparing tumor
microenvironment composition and cell-cell signaling between
model-derived risk groups. Requires the R packages in
[requirements_R.md](../requirements_R.md). Run the numbered scripts in
order; where a stage has multiple files (see the file-naming note
above), run the latest/most-revised one unless you specifically need an
earlier variant:

1. **`01_QC.R`** — loads CellRanger output, quality filtering
   (mitochondrial %, feature/count thresholds), saves QC'd Seurat
   object.
2. **`02_Integration.R`** — normalization, Harmony batch integration,
   clustering (multiple resolutions), UMAP.
   `02_RemoveSuspectedDoublet2rd.R` / `02_RemoveSuspectedDoublet3rd.R`
   — iterative doublet-cluster removal + re-integration rounds
   (`scDblFinder`-flagged and UMAP-identified suspicious clusters);
   `03_RemoveSuspectedDoublets.R` is a further/alternative round.
3. **`03_CellTypeAnnotation_1step.R`** / **`_2step.R`** — marker-based
   cell-type annotation of the integrated, doublet-cleaned object;
   `03_CellType_Annotation.R` is a revised combined version;
   `03_CellTypeAnnotation_Heatmap.R` produces the marker-gene
   validation heatmap.
4. **`04a_CD8_Subtyping_and_Analysis.R`** — high-resolution CD8 T-cell
   sub-clustering. **`04a_Proportion_Boxplot.R`** — cell-type
   proportion boxplots + Wilcoxon test, model risk group vs. cell-type
   abundance. **`04_Differential_Analysis.R`** /
   **`04_DifferentialExpressionAnalysis.R`** /
   **`04_Proportion_DEG_SignificantClusters.R`** /
   **`04b_AllClusters_Proportion_DEG.R`** — per-cluster differential
   expression between risk groups (volcano plots), with
   `04_Proportion_DEG_SignificantClusters.R` first identifying which
   clusters differ significantly in proportion before running DE on
   those.
5. **`05_CNV_Analysis.R`** / **`05_CNV_UMAP.R`** — copy-number-variation
   inference (`infercnv`) to distinguish malignant from non-malignant
   epithelial cells, visualized as a CNV score split by risk group.
   **`05_Pathway_Enrichment_CAF.R`** — GO/KEGG/GSEA (Hallmark, Reactome)
   pathway enrichment on cancer-associated fibroblast (CAF) DEGs.
6. **`06_CellChatAnalysis.R`** / **`06_CellChat_CAF_Communication.R`**
   — `CellChat` cell-cell communication analysis, with the latter
   focused specifically on CAF → other-cell-type signaling, comparing
   Low-risk vs. High-risk groups. **`06a_CirclePlots.R`** — the
   corresponding circle-plot visualization of significant
   ligand-receptor pairs.
7. **`07_Biological_Basis_CT_Response.R`** — final synthesis: ties the
   immune/stromal composition and signaling differences found above
   back to the CT-imaging-derived risk score, addressing what
   distinguishes the tumor microenvironment of predicted responders vs.
   non-responders and what that implies about resistance mechanisms.

## Notes on reproducing published figures

- **Model colors** are consistent across all figures: Spatial = `#E74C3C`
  (red), Radiomics = `#3498DB` (blue), Fusion/SRP = `#009E73` (green).
- **Figure sizing** follows Nature journal conventions
  (`PlotFigures.py`): single column = 3.5in, double column = 7.2in,
  ~6-8pt sans-serif fonts, 300dpi.
- Random seeds are fixed at **42** everywhere bootstrap resampling or
  permutation testing is used (`BinormalAUC_BootstrapCI.py`,
  `RNAseq_Enrichment_Analysis.py`'s GSEA prerank, etc.), for
  reproducibility.
